# Maintainer repository settings

These are GitHub UI/account settings, separate from committed files. A document or CODEOWNERS file does not automatically enforce them.

## Suggested presentation

Description: Maintainer-governed AI contributions to open source. Bring your coding agent; follow the project's rules.

Topics: open-source, ai-agents, coding-agents, developer-tools, cli, golang, codex, harness, contributor-tools.

Social preview: upload assets/social-preview.png in the repository's social-preview settings.

## Before inviting external contributors

- [ ] Configure a private vulnerability reporting/contact route and verify it works.
- [ ] Publish a suitable confidential conduct contact.
- [ ] Review main-branch rules against the actual CI names after the first checks pass.
- [ ] Avoid a review requirement that the sole maintainer cannot satisfy for their own PRs.
- [ ] Confirm workflow token permissions and third-party action policy.
- [ ] Keep runtime task labels separate from the implementation backlog.
- [ ] Set release permissions only when packaging and readiness evidence exist.

The bootstrap does not claim these settings were changed merely because the related documents exist. Follow the actual repository settings and the release checklist.
