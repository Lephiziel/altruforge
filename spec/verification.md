# Verification and publication

## Local gate

Before a Draft PR is published, the runtime MUST confirm that the diff stays within policy, the selected task has usable acceptance criteria, required checks completed successfully, and an independent review session produced no blocking finding.

A check result includes its ID, observed exit code, timeout state, and pass/fail result. Missing output or a model-written claim cannot substitute for a check result.

The agent cannot change the pinned verifier policy. Changes to existing tests require review and an explanation; removing evidence to obtain a green result is not completion.

## Project gate

The project treats the local report as untrusted input. Its own CI verifies the proposed commit using trusted policy and safe workflow permissions.

A status or attestation must identify the exact commit and policy it verified. A label such as "generated by Altruforge" provides provenance context only.

Never execute untrusted PR code with a privileged upstream token through `pull_request_target` or an equivalent pattern.

## Publication

The trusted publisher uses the contributor's GitHub identity. It rechecks current lease authority and the immutable result, records publication intent durably, and reconciles existing PRs on retries.

The PR is a draft. Its description includes the task, resulting behavior, observed checks, scope, limitations, base/result references, policy digest, and stable run ID. It must disclose AI assistance without claiming provider endorsement.
